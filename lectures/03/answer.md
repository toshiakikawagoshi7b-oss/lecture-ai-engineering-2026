## 演習

- 第1回（素のLLM）とエージェントの回答の違い：「AIE2026の講座の宿題にある「3レベル」とは何ですか？」で比べた
  - 第1回（`app.ask`）：「〜を指している可能性が非常に高い」と推測で答え、一般的な講座の例として「レベル1〜3（初心者・中級者・経験者向け）」を説明した。実際の構成（基礎・実装・発展）とは名前も中身も違い、「1〜2を選ぶことが多い」という説明も誤り
  - エージェント（`app.agent`）：用語集を検索し、「基礎（講義内容の確認）・実装（自分でコードを書く）・発展（調査や試行）の3段階で、どれか1つに取り組めば完了。原則として採点はしない」と、用語集の定義どおりに答えた。末尾にこの用語を扱う「第1回」も示した
  - 素の LLM は講座に固有のことを知らないので、もっともらしい一般論で埋めてしまう。エージェントは確かな情報源（用語集）を引いてから答えるので、短く正確になった
- `--trace` で見えたツール呼び出し（ツール名と引数）：「LoRAとQLoRAの違いは？」に対して、`search_glossary({'query': 'LoRA'})` と `search_glossary({'query': 'QLoRA'})` の2回。docstring の「query には調べたい用語を1つだけ入れる」に従い、用語ごとに分けて検索していた。回答の最後には `INSTRUCTIONS` の指示どおり「関連する回：第2回」が付いた
- 1つの質問での LLM 呼び出し回数（`requests`）：2回（tool_calls=2）。1回目の応答でモデルが2つの検索をまとめて依頼し、2回目で検索結果を見て回答を書いた。ツールを2回呼んでも、同じ応答の中でまとめて依頼すれば LLM の呼び出しは増えない
- 追加したツールと、docstring に書いた説明：
  - `make_quiz(lecture: int)`：指定した回の用語を用語集から1つ選び、「○○の意味は？」という問題と答え（定義）を JSON で返す。用語がない回（第0回など）は、問題を作れる回の一覧を返す
  - docstring：「指定した回の用語から確認問題を1問作り、問題と答えをJSONで返す。『第2回の確認問題を出して』『理解度をチェックしたい』のように、復習や確認のための問題を求められたときに使う。返ってきた answer は、利用者が答えるまで見せずに、まず question だけを出題すること」
  - `INSTRUCTIONS` にも「確認問題を求められたら make_quiz を使い、答えは利用者が回答するまで見せない」を追加
  - 動作確認：`uv run python -m app.agent --trace "第2回の内容から確認問題を1問出して"` で `make_quiz({'lecture': 2})` が1回呼ばれ（requests=2）、第2回の「エポック」が出題された。答えは表示せず利用者の回答を待つ形になり、docstring の指示が守られた。宿題・基礎の条件C では回を取り違えたが、今回は質問で回を指定したため正しい回が渡された
